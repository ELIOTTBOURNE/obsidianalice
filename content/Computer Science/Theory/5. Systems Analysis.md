### **System Development Approaches**

#### **1. Waterfall Model**

**Nature**:

- Linear, sequential approach with distinct phases
- Each stage must be fully completed before moving to the next

**Key Stages**:

1. Requirements → 2. Design → 3. Implementation → 4. Testing → 5. Maintenance

**Advantages**:  
✔ Clear milestones and deliverables  
✔ Thorough documentation at each stage  
✔ Easier to estimate costs/timelines upfront  
✔ Smooth handover if staff changes occur

**Disadvantages**:  
✖ Inflexible to changing requirements  
✖ Errors in early stages can be costly to fix later  
✖ Limited client involvement after requirements stage  
✖ Working product only available late in process

**Best for**:

- Projects with well-defined, stable requirements
- Safety-critical systems (e.g., medical software)

---

#### **2. Agile Model**

**Nature**:

- Iterative approach with continuous feedback
- Work is done in short cycles (sprints, typically 2-4 weeks)

**Key Principles**:  
• Working software over comprehensive documentation  
• Responding to change over following a plan  
• Frequent client collaboration

**Advantages**:  
✔ Adaptable to changing requirements  
✔ Early and regular delivery of working features  
✔ Continuous client feedback improves final product  
✔ Issues identified and fixed early

**Disadvantages**:  
✖ Less predictable timelines/budgets  
✖ Requires high client availability  
✖ Can be harder to maintain without thorough documentation  
✖ Not ideal for highly regulated industries

**Best for**:

- Projects with uncertain/evolving requirements
- Web/mobile applications
- Startups and innovative products

**Common Variants**:

- Scrum
- Kanban
- Extreme Programming (XP)

### **Documentation Through Development Stages**

#### **1. Requirements Stage**

• **Feasibility Study** (economic, technical, legal analysis)  
• **Requirements Specification** document  
• User stories (Agile) / Use cases (Waterfall)

#### **2. Design Stage**

• **System Design Document**  
• Data dictionaries  
• Diagrams:

- ERD (Entity Relationship)
- DFD (Data Flow)
- UML diagrams

#### **3. Implementation Stage**

• **Source code with comments**  
• Version control logs  
• API documentation

#### **4. Testing Stage**

• **Test plans** and test cases  
• Bug reports  
• User acceptance test results

#### **5. Maintenance Stage**

• **Technical manuals**  
• **User guides**  
• Change logs  
• Maintenance schedules

### **Comparison Table: Waterfall vs Agile Documentation**

|**Aspect**|**Waterfall**|**Agile**|
|---|---|---|
|**Amount**|Extensive, formal documentation|Minimal, just enough documentation|
|**Timing**|Created upfront and per phase|Evolves throughout project|
|**Focus**|Process-oriented|Working software-oriented|
|**Examples**|SRS documents, detailed specs|User stories, sprint backlogs|

---

### **Key Takeaways**

1. **Waterfall** suits projects with fixed requirements needing strict compliance
2. **Agile** excels when flexibility and rapid iteration are valuable
3. Documentation in Waterfall is **comprehensive and phase-specific**
4. Agile focuses on **working software** with lighter documentation
5. The choice depends on:
    - Project complexity
    - Requirement stability
    - Client involvement needs
    - Regulatory constraints
